CivicFix

The complete product definition: four screens, one loop, no accounts.

The Core Journey

Flagged for your confirmation

Synthesis, not your explicit words: category selection is folded into the Review step (editable field, left open when confidence is low) rather than a separate manual-selection screen before the photo. This reconciles "AI auto-classifies" with "let me pick it myself if needed" without adding an extra screen. If you pictured a separate category-picker screen, say so and I'll adjust.

States and Boundaries

First use — Capture screen, photo prompt front and center, nothing else required.
Low-confidence classification — category field left open on Review for manual pick, no error shown.
No verified authority found — falls back to the general GHMC grievance portal, clearly labeled as a fallback.
Location permission denied — flow continues; complaint notes "location not provided."
Success — real official portal opens with the complaint ready; filed for real on camera for the demo.
Persistence — none. No accounts, no saved history for the POC.

Scope of This Build

Building In this proof of concept
  • Single-flow mobile web app: Capture → Pipeline animation → Review (editable) → Hand-off.
  • Photo capture/upload, optional text description, browser geolocation.
  • Vision classification into 3 categories, with graceful manual fallback on low confidence.
  • Grounded authority research with cited sources, general-portal fallback when unverified.
  • Editable complaint draft including filer name/contact.
  • Hand-off link to the real official channel (or fallback portal).
Deferred Implied, but not now
  • Accounts/login + saved history — no reason to persist per-user data for a single demo.
  • Voice input — typed description is the reliable v1 path; voice is a polish layer after the core loop works.
  • Cities beyond Hyderabad — architecture allows extension; only Hyderabad is verified here.
Non-goals Explicitly not doing this
  • Automated government submission / live status tracking. No public API; faking it misrepresents functionality.
  • Citing specific municipal code/legal sections. Real hallucination risk — replaced with cited-source process instead.
  • Native Android/iOS app. Browser APIs cover everything needed.
  • Login/accounts for v1. See Product Decisions in prd.md.
