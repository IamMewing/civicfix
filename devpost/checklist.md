## Revisions

- **Model changed from `gemini-2.5-flash` to `gemini-3.8-flash`** — slice 1's real test call returned a `404`: Gemini confirmed `gemini-2.5-flash` is no longer available to new API keys and pointed directly to `gemini-3.8-flash`.
- **Google Search grounding dropped from the architecture; `authorities.json` promoted from "backing/cross-check" to the primary source of truth.** Slice 1's real grounding test call returned a persistent `429` quota error that survived a 30-second backoff retry. Investigation (checked Google's own Gemini API pricing page directly) confirmed: Google Search grounding is listed as "Not available" on the free tier for `gemini-3.8-flash` — it requires an active paid billing tier (a card linked to the Google Cloud/AI Studio project), even though the first 5,000 grounded searches/month would then be free. This conflicts with the learner's stated constraint of no API credits/payment method (`learner-profile.md`). This touches `scope.md > The Unique Kernel`, so it was brought to the learner directly rather than silently patched; the learner chose the no-billing option. New approach: real authority research is done once, by the agent, via genuine web search during the build (not fabricated), and the verified, cited results are stored in `src/data/authorities.json`. At runtime, the model reasons over this verified data (passed directly in the prompt) and produces a correctly cited authority recommendation — no live grounding tool call, so no billing requirement and no rate-limit risk on demo day. The "agent investigates and cites sources" story stays true; the citations are gathered once during build instead of fetched live on every request. See `scope.md > The Unique Kernel` and `spec.md > Stack` for the updated wording.
- **Two reliability fixes found during the learner's own testing.** (1) Location was shown as raw latitude/longitude everywhere — in the UI and in the drafted complaint text. Added `/api/geocode`, a reverse-geocoding route using OpenStreetMap's free Nominatim service (no key, no billing, same no-cost constraint as the rest of the stack), so the app now shows a readable area name (e.g. "Madhapur, Hyderabad") with the precise coordinates kept alongside it in the drafted complaint for repair crews. Degrades gracefully to coordinates if the geocoding call fails. (2) Uploading a photo that wasn't a civic issue at all (the learner tried a person's face) still ran research and drafted a generic "General Civic Grievance" complaint — `/api/classify` only ever said "uncertain," which the pipeline treated the same whether the photo was a genuinely ambiguous civic problem or not a civic photo at all. Added an explicit `isCivicIssue` field to the classification so the two cases are distinguished: a real-but-ambiguous civic photo still auto-routes to the general fallback and drafts as before, but a non-civic photo stops the pipeline after classification and asks the person to confirm the category themselves rather than silently drafting a nonsense complaint.
- **A new slice (9) added after the original 8-slice plan was already marked complete.** After the learner reviewed slice 8's result end to end (a recorded walkthrough of the full core loop, including the real GHMC site opening), they explicitly rejected treating it as final and asked for a marketing landing page with the production quality of a reference design-studio site (Buttermax: bold saturated color, huge display type, confident motion), plus a more premium feel in the tool itself. Buttermax's own maximalist studio-portfolio palette (saturated yellow/black) wasn't carried over literally — CivicFix is a civic safety tool people need to trust, not a design-agency showcase — but its production value was: a new civic-bold palette (marigold/ink/paper plus three fixed category accent colors), Archivo as a bold display typeface, pill-shaped buttons, and one signature motion moment on the new landing page's hero. The app now has two routes: `/` (the new landing page) and `/app` (the tool, restyled onto the same tokens); the PWA manifest's `start_url` was moved to `/app` accordingly. See Slice 9 above.
- **AI provider switched from Google Gemini to Groq entirely.** Even after the grounding fix above, slice 1's plain (non-grounding) vision and reasoning calls to `gemini-3.8-flash` kept failing with the same persistent `429 quota exceeded` error — on a fresh run, after waiting a full minute, with only a handful of total requests made. This matches a documented, unresolved Google-side account/project provisioning bug reported by other free-tier developers (not a rate limit we were actually hitting, and not something fixable from our code or by waiting). The learner confirmed Groq over the alternatives considered (AWS and Google Cloud Run both require a card at account signup regardless of which service is used, so neither solves the no-cost constraint). Groq's free tier needs no credit card and has generous limits (30 requests/min, 1,000/day for the model used here). The SDK changed from `@google/genai` to `groq-sdk`, and the model used for both vision and reasoning is `qwen/qwen3.8-27b` (Groq's vision-capable model, OpenAI-compatible `chat.completions.create` call shape). `src/data/authorities.json` and the overall pipeline design (classify → research → draft) are unchanged — only the underlying model call changed. `scripts/test-gemini.ts` is replaced by `scripts/test-groq.ts`. See `spec.md > Stack` for the updated wording.
- **Two more fixes from the learner's own testing of slice 9, not yet logged at the time.** (1) After manually overriding the category on the capture screen (e.g. correcting a mis-detected "person's face" to "pothole"), the result card kept showing the *original* reasoning text ("the image shows a person's face...") underneath the now-corrected category and 100% confidence — self-contradictory, even though the override itself was working as intended (same "trust the manual correction" pattern as the Review screen's own category dropdown). Fixed by having the override also replace `reasoning` with a plain "Category corrected manually by the reporter." string, so the card never shows text that contradicts the category it's displaying. (2) The Hand-off button's label text, pulled straight from `authorities.json`'s `reportingChannelLabel` field, was the full verbose source description (e.g. `GHMC "How Do I..." citizen services page (grievance registration + My GHMC app)`) rather than a short, professional button label — correct data, wrong field length for a button. Shortened `reportingChannelLabel` to a few words per entry (e.g. "GHMC Complaints Portal") while leaving every other verified field (`authorityName`, `reportingChannel`, `sourceNote`) untouched; the longer description still lives in `sourceNote`, shown separately. This also surfaced that `/api/research/route.ts` caches `authorities.json` in memory for the life of the dev-server process (`authoritiesCache`), so a data-only edit needs a full server restart, not just a browser refresh, to take effect — worth knowing for any future `authorities.json` edit.
