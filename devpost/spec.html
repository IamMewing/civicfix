CivicFix — Technical Spec

The blueprint for how the PRD actually gets built: one Next.js app, one AI provider, zero database.

How This Works, In Plain Language

CivicFix is a website you open on your phone's browser — no app install, no login. You take or upload a photo of a civic problem. That photo, plus what you typed and your location, goes to the site's own backend — a few small server functions living in the same project as the website.

The backend calls Google's Gemini AI three times in a row: once to look at the photo and say what kind of problem it is, once to search the web for which Hyderabad authority actually handles it (and show where it found that out), and once to turn all of it into a properly written complaint. Each call happens for real, one after another — the pipeline animation on screen is tied directly to them finishing, not a fake loading bar.

You then see the finished complaint, can edit anything that looks wrong, and tap a button that opens the real government website so you can file it yourself. Nothing is saved anywhere — no database, no account. The only "memory" the app has is a small file of pre-verified official sources it checks its own research against, so it can't confidently invent an authority that doesn't exist.

The Core Journey Through the System

The Journey, Step by Step

1User opens the site on their phone → Capture step renders. Photo, optional description, location permission — all held as browser state, nothing sent yet.
2Tap "Analyze" → Pipeline step. Three calls fire in sequence: /api/classify → /api/research → /api/draft. Each icon updates the moment its real call resolves.
3Review step: every field pre-filled and editable — category, location, description, authority, filer name/contact.
4Tap "Open Official Reporting Channel" → Hand-off step opens the real government portal and shows the complaint text ready to copy in.
5Nothing is written back to CivicFix. Refresh starts a brand-new, empty report.

Stack

  • Next.js 14 (App Router) + React + TypeScript — one project, frontend and backend together, so the API key never reaches the browser.
  • Tailwind CSS — fast, polished mobile styling without a hand-built design system.
  • Framer Motion — the premium animation requirement lives here: the pipeline step and screen transitions.
  • Google Gemini 2.5 Flash — free tier, no credit card, confirmed free image input + free Search grounding (≤500/day). One provider for all three AI steps.
  • No database, no auth — each report is one in-browser session; matches the PRD's deferred accounts/history decision.

Components

CaptureStep
Photo capture/upload, description textarea, location permission. Holds local form state until "Analyze" is tapped.
prd.md > Capture
PipelineAnimation
Fires the three sequential API calls; animates each step's state as its real fetch resolves.
prd.md > Pipeline animation
ReviewStep
Renders the draft as editable fields. Category defaults to the AI's pick, or stays blank if confidence was low.
prd.md > Complaint drafting and review
HandoffStep
Shows the finished complaint text (copyable) and the button that opens the real portal, or the general fallback.
prd.md > Hand-off
/api/classify, /api/research, /api/draft
Server-side route handlers — the only place the Gemini API key is used. Each does exactly one of the three AI steps.
prd.md > Vision classification, Authority research, Complaint drafting
authorities.json
Pre-verified official sources for the 3 categories + the general GHMC fallback. Populated with real, verified URLs as the first real research task of the build.

Flagged — Verify Early in the Build

Not fully confirmed: Google stopped publishing exact Gemini free-tier rate limits, and third-party sources disagree on the newest models' numbers. Google's own pricing page states Search grounding is free up to 500 requests/day on gemini-2.5-flash specifically — far more than this project needs — but the exact current SDK package name and call syntax should be checked against the live docs as the very first technical step, before building the pipeline on top of it.
Not yet real: authorities.json's official URLs for GHMC / TGSPDCL / TSSPDCL / HMWSSB are placeholders until verified. Populating this with real, checked sources is a build task, not a design decision — it doesn't block this spec's approval.

Important Failure Modes

A Gemini call is slow or fails → plain "taking longer than expected" message with a retry button, not a silent hang.
Low-confidence classification → category field left blank on Review for manual pick, no error shown.
No verified authority found → falls back to the general GHMC portal, clearly labeled as a fallback.
Location permission denied → flow continues; complaint notes "location not provided."
